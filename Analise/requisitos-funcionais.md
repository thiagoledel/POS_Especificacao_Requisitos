# Atividade 1 - Identificação dos Requisitos Funcionais

## Sistema de Gestão de Eventos - Eventus

### Objetivo

Identificar os requisitos funcionais do sistema com base nas informações obtidas durante as entrevistas com os stakeholders e no contexto de negócio apresentado.

---

# RF01 - Consultar Eventos Disponíveis

**Descrição:** O sistema deve permitir que os participantes visualizem todos os eventos disponíveis para inscrição.

**Stakeholder(s):** Participantes

---

# RF02 - Consultar Detalhes de Evento

**Descrição:** O sistema deve permitir a visualização das informações detalhadas de um evento, incluindo programação, vagas disponíveis e informações gerais.

**Stakeholder(s):** Participantes

---

# RF03 - Realizar Inscrição em Evento

**Descrição:** O sistema deve permitir que um participante realize sua inscrição em um evento.

**Stakeholder(s):** Participantes

---

# RF04 - Realizar Inscrição em Workshops

**Descrição:** O sistema deve permitir que um participante realize inscrição em workshops vinculados a um evento.

**Stakeholder(s):** Participantes

---

# RF05 - Emitir Comprovante de Inscrição

**Descrição:** O sistema deve gerar um comprovante após a realização de uma inscrição.

**Stakeholder(s):** Participantes

---

# RF06 - Consultar Inscrições Realizadas

**Descrição:** O sistema deve permitir que o participante consulte suas inscrições realizadas.

**Stakeholder(s):** Participantes

---

# RF07 - Cancelar Inscrição

**Descrição:** O sistema deve permitir que o participante solicite o cancelamento de uma inscrição.

**Stakeholder(s):** Participantes

---

# RF08 - Emitir Certificado

**Descrição:** O sistema deve permitir que o participante emita certificados referentes aos eventos realizados.

**Stakeholder(s):** Participantes

---

# RF09 - Criar Evento

**Descrição:** O sistema deve permitir que organizadores cadastrem novos eventos.

**Stakeholder(s):** Organizadores

---

# RF10 - Alterar Evento

**Descrição:** O sistema deve permitir que organizadores atualizem informações de eventos cadastrados.

**Stakeholder(s):** Organizadores

---

# RF11 - Gerenciar Programação do Evento

**Descrição:** O sistema deve permitir a definição e manutenção da programação dos eventos e workshops.

**Stakeholder(s):** Organizadores

---

# RF12 - Definir Quantidade de Vagas

**Descrição:** O sistema deve permitir que organizadores definam a quantidade máxima de vagas de cada evento ou atividade.

**Stakeholder(s):** Organizadores

---

# RF13 - Controlar Vagas Automaticamente

**Descrição:** O sistema deve controlar automaticamente a disponibilidade de vagas com base nas inscrições realizadas.

**Stakeholder(s):** Organizadores

---

# RF14 - Encerrar Inscrições por Lotação

**Descrição:** O sistema deve impedir novas inscrições quando o limite de vagas for atingido.

**Stakeholder(s):** Organizadores

---

# RF15 - Gerenciar Lista de Espera

**Descrição:** O sistema deve permitir a inclusão de participantes em lista de espera quando não houver vagas disponíveis.

**Stakeholder(s):** Organizadores, Participantes

---

# RF16 - Permitir Configuração de Cancelamento

**Descrição:** O sistema deve permitir configurar eventos que aceitam ou não cancelamento de inscrição.

**Stakeholder(s):** Organizadores

---

# RF17 - Acompanhar Inscrições em Tempo Real

**Descrição:** O sistema deve disponibilizar informações atualizadas sobre a quantidade de inscritos em cada evento.

**Stakeholder(s):** Organizadores

---

# RF18 - Gerenciar Participantes

**Descrição:** O sistema deve permitir aos organizadores consultar e administrar os participantes inscritos.

**Stakeholder(s):** Organizadores

---

# RF19 - Consultar Relatório de Inscritos

**Descrição:** O sistema deve disponibilizar relatórios contendo informações sobre os inscritos nos eventos.

**Stakeholder(s):** Organizadores

---

# RF20 - Registrar Modalidade do Evento

**Descrição:** O sistema deve permitir configurar eventos gratuitos ou pagos.

**Stakeholder(s):** Equipe Financeira, Organizadores

---

# RF21 - Registrar Pagamento

**Descrição:** O sistema deve permitir o registro dos pagamentos realizados pelos participantes.

**Stakeholder(s):** Equipe Financeira

---

# RF22 - Confirmar Pagamento

**Descrição:** O sistema deve permitir a confirmação dos pagamentos efetuados.

**Stakeholder(s):** Equipe Financeira

---

# RF23 - Liberar Inscrição Após Confirmação de Pagamento

**Descrição:** O sistema deve permitir a ativação ou confirmação de inscrições condicionadas ao pagamento.

**Stakeholder(s):** Equipe Financeira

---

# RF24 - Registrar Solicitação de Reembolso

**Descrição:** O sistema deve permitir registrar solicitações de reembolso referentes a inscrições canceladas.

**Stakeholder(s):** Participantes, Equipe Financeira

---

# RF25 - Processar Reembolso

**Descrição:** O sistema deve permitir o controle e processamento dos reembolsos autorizados.

**Stakeholder(s):** Equipe Financeira

---

# RF26 - Consultar Situação Financeira da Inscrição

**Descrição:** O sistema deve permitir consultar o status financeiro da inscrição, como pendente, pago, reembolsado ou cancelado.

**Stakeholder(s):** Participantes, Equipe Financeira

---

# RF27 - Consultar Programação do Evento

**Descrição:** O sistema deve permitir que palestrantes consultem a programação das atividades relacionadas aos eventos.

**Stakeholder(s):** Palestrantes

---

# RF28 - Consultar Participantes das Atividades

**Descrição:** O sistema deve permitir que palestrantes consultem os participantes inscritos em suas atividades.

**Stakeholder(s):** Palestrantes

---

# RF29 - Enviar Notificações aos Participantes

**Descrição:** O sistema deve enviar notificações relacionadas a inscrições, cancelamentos, pagamentos e certificados.

**Stakeholder(s):** Participantes, Organizadores

---

# RF30 - Manter Cadastro de Usuários

**Descrição:** O sistema deve permitir a administração dos usuários dos diferentes perfis do sistema.

**Stakeholder(s):** Equipe de TI

---

# RF31 - Manter Perfis de Acesso

**Descrição:** O sistema deve permitir a configuração dos perfis de acesso dos usuários conforme seu papel no sistema.

**Stakeholder(s):** Equipe de TI

---

# RF32 - Manter Dados do Sistema

**Descrição:** O sistema deve permitir atividades administrativas necessárias para manutenção operacional da plataforma.

**Stakeholder(s):** Equipe de TI

---

# Requisitos Funcionais Identificados como Pendentes de Especificação

Os requisitos abaixo foram identificados, porém necessitam de detalhamento adicional durante a análise de requisitos:

| ID | Requisito | Pendência |
|---|---|---|
| RF15 | Gerenciar Lista de Espera | Não foram definidas as regras de funcionamento da lista de espera. |
| RF07 | Cancelar Inscrição | Não foi definido o prazo limite para cancelamento. |
| RF24/RF25 | Reembolso | Não foram definidos os critérios para concessão de reembolso. |
| RF08 | Emitir Certificado | Não foi definido se a emissão será automática ou condicionada à presença. |
| RF29 | Enviar Notificações | Não foi definido o canal de envio, como e-mail, SMS, aplicativo ou outro meio. |
| RF23 | Liberar Inscrição Após Pagamento | Não foi definido o momento da reserva da vaga durante o processo de pagamento. |
| RF04 | Inscrição em Workshops | Não foi definida a regra para tratamento de conflitos de horários. |
| RF28 | Consultar Participantes das Atividades | Não foram definidos quais dados dos participantes poderão ser visualizados pelos palestrantes. |
